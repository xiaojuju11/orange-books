# 第 9 章 AI 做的界面，为什么总差一点

> 不难看，是**没有决策**。

## 为什么需要它

让 AI"做一个好看的落地页"，你大概会得到：紫蓝渐变、居中大标题、三张卡片、圆角按钮、轻微阴影。

单看每个元素都挑不出错，合在一起就是"见过一百次"。

这种产出有个名字：**AI Slop**——精致但没有主张的东西。

## 为什么会 Slop

模型是在海量网页上训练的。当你不给任何约束，只说"做一个好看的页面"，它的最优策略是**取训练数据里出现频率最高的那套组合**：最常见的字体、最保险的配色、最流行的布局。

频次最高的东西，必然是最没特点的东西——因为它被最多人用过。

所以问题不是"它审美差"，是**你在让它对平均数负责**。平均数不丑，只是不表达任何东西。

## 术语表

| 术语 | 人话 | 类比 |
| --- | --- | --- |
| Slop | 精致但无主张的产出 | 酒店大堂的装饰画 |
| 设计 token | 颜色、字号、间距的固定档位 | 装修的材料清单 |
| 主张 | 这个页面最想让人记住的一件事 | 一句话电梯陈述 |

## 三个能真正改变结果的决策

### 一、每页只留一个主张

先回答问题：**这个页面最想让人做的一件事是什么？**

如果是"注册试用"，那大标题、按钮、留白全部为它服务，其他元素一律降级或删掉。AI 默认会把所有信息平铺，因为它不知道哪个重要。

一句话告诉它，布局会完全不同：

```text
这个页面只有一个目标：让人点"免费试用"。
其他所有内容（功能列表、案例、FAQ）都只能是次要信息，
视觉权重不能超过那个按钮。
```

### 二、先定 token，再让它画

"配色高级一点"是形容词，它只能猜。给具体档位，它就有约束：

```text
设计 token（不许新增）：
- 背景：#FAFAF8，卡片：#FFFFFF
- 文字：#1A1A1A（主）、#6B6B6B（次）
- 主色只有一个：#C2410C，只用于主按钮和当前选中态
- 字号：12 / 14 / 16 / 24 / 40，不许出现 18、20、32
- 圆角：8（卡片）、999（标签）
```

约束越具体，Slop 越少。因为**没有发挥空间的地方，它就不会去取平均值**。

### 三、给参考，别给形容词

"要克制""要高级""要有呼吸感"——这三个词它能给你一百种理解。

换成一句：

```text
参考 Linear 的定价页：大量留白，只有一处强调色，文字不用纯黑。
不要照抄布局，只学它的克制程度。
```

参考物是一个坐标系，形容词不是。

## 翻车现场

::: warning 做了七版，每版都"还行"
提需求："做一个数据分析的落地页，要专业一点。"

七版之后，你把七张截图并排放在一起，发现它们是同一个页面的七个变体：同一个渐变、同一套卡片、同一个居中标题。区别只有颜色深浅。

问题在于每一轮你给的都是形容词（"更专业""更简洁"），而形容词只能让它在平均数附近微调，永远跳不出去。

第八版你换了个说法："参考 Stripe 的开发者文档首页，学它怎么用留白和等宽字体制造技术感。主色只用一处。" 这一版不一样了。
:::

## 用规则管，别用审美管

审美是主观的，规则不是。"这个按钮太重"没法执行，"主色只允许出现在主按钮和选中态"可以执行。

所以第四次之后我改成两步：

1. 把设计 token 和三条硬规则写进 `AGENTS.md`；
2. 每次让它做页面前，先让它读一遍。

规则一旦写下来，就变成每次都会被检查的东西，不再依赖你当面描述。

## 自测三问

1. 你上一次说"好看一点"，具体想改的是什么？如果说不出来，是不是本来就没想清楚？
2. 你的项目有设计 token 吗？如果没有，哪些地方正在各自为政？
3. "参考某个具体的页面"和"参考某种风格"，产出差别为什么那么大？

## 到这里

这本书的四部分——委托、上下文、验收、需求与设计——串起来是一条闭环：

```text
说清楚要什么 → 给它干净的上下文 → 让它做得少而准
→ 让机器验收 → 让自己看见界面 → 从决策出发做设计
```

少任何一环，都会在别的地方加倍还回来。
